Qué es un CLI y dónde se consigue

datablog bash-shell
Actualizado: 2026-11-14
En video corto · 3

1. Qué es un CLI

CLI significa Command Line Interface: interfaz de línea de comandos. Es una forma de usar un programa escribiendo instrucciones en la terminal, en lugar de hacer clic en botones.

La palabra clave es interfaz: la puerta por la que entras a un programa. Un mismo programa puede tener varias.

Programa Puerta con ventanas Puerta por comandos (CLI)
Docker Docker Desktop docker
Amazon Web Services La consola web aws
Visual Studio Code El editor code

1.1 Un ejemplo: recortar un video

Con la interfaz visual: un clic para subir el video, un par de clics para recortarlo y otro para exportarlo.

Con el CLI de ffmpeg, una sola línea:

ffmpeg -i video.mp4 -ss 10 -to 20 recorte.mp4
Parte Qué hace
ffmpeg El programa
-i video.mp4 El video que se va a usar
-ss 10 Desde el segundo 10
-to 20 Hasta el segundo 20
recorte.mp4 Cómo se llamará el video nuevo

1.2 Por qué importa ahora

Escribir comandos parece más difícil que hacer clic. Pero hoy no siempre los escribes tú: un agente de IA puede hacerlo por ti. Le pides en lenguaje natural "corta este video" y por detrás ejecuta el comando.

Un agente que hace clics como una persona (con extensiones que mueven el mouse) es lento: el programa tiene que estar abierto y gasta memoria. Si el programa tiene CLI, el agente entra directo por esa puerta.

La pregunta que vale la pena hacerse con cada programa que usas: ¿existe una versión por comandos?

2. Las tiendas de tu computadora: gestores de paquetes

En el celular instalas aplicaciones desde la App Store o la Play Store. En la computadora, para los programas por comandos, existe algo parecido: el gestor de paquetes.

Un paquete es la caja en la que viaja un programa. El gestor la busca, la descarga, la abre y deja el programa listo. Todo con un comando: instalar y el nombre del programa.

Sistema Gestor ¿Viene instalado? Ejemplo
Mac Homebrew No, se instala una vez brew install ffmpeg
Windows winget Sí, en Windows 11 y Windows 10 desde la versión 1809 winget install <programa>
Linux (Ubuntu, Debian) apt Sí sudo apt install ffmpeg

2.1 Cómo sabe el gestor dónde está cada programa

El gestor tiene un catálogo de recetas, una por programa. Al instalar:

  1. Busca la receta del programa en su catálogo.
  2. La receta dice de dónde sale el programa (normalmente de quien lo creó) y cómo instalarlo.
  3. El gestor sigue la receta y te entrega el programa listo.

La receta de ffmpeg en Homebrew apunta al código oficial de ffmpeg.org e incluye su huella (sha256), para comprobar que lo descargado no cambió.

2.2 No es solo para programas pequeños

En nuestra Mac instalamos con Homebrew el CLI de Azure (brew install azure-cli) y PostgreSQL, una base de datos (brew install postgresql@17). Una línea cada uno.

La tienda es la forma más rápida y cómoda, pero no la única ni siempre la mejor: algunos programas prefieren que los instales con el comando de su página oficial.

3. Si no está en la tienda

Si el gestor responde que no encuentra el programa, nadie escribió todavía su receta para esa tienda. Y a veces el programa sí está, pero su página oficial recomienda otra forma. En los dos casos, la respuesta está en la página oficial, y casi siempre es una de estas:

Forma Cómo es Ejemplos en nuestra Mac
Línea de instalación Una línea para pegar en la terminal, que descarga instrucciones y las ejecuta Claude Code, Homebrew, nvm
Instalador de siempre Un .pkg en Mac o un .exe/.msi en Windows, con doble clic o desde la terminal Python, el CLI de AWS
Catálogo del fabricante Una línea agrega a Homebrew el catálogo de la empresa (brew tap) y desde ahí se instala igual El CLI de ElevenLabs
Descargarlo tú mismo Bajar el archivo desde la página del proyecto (muchas veces en GitHub) o compilar el código Ninguno

La regla: antes de instalar, mira qué recomienda la página oficial del programa. Muchas veces te dirá que uses la tienda de tu sistema; otras, una de estas formas.
