El path: por qué la terminal no encuentra lo que instalaste

datablog bash-shell
Actualizado: 2026-11-18
En video corto · 4

1. El archivo que se lee cada vez que abres la terminal

Cada vez que abres la terminal en Mac, antes de que escribas nada, lee un archivo tuyo y sigue las instrucciones que tenga.
Nombre .zshrc
Dónde está En tu carpeta personal (~/.zshrc)
Por qué ese nombre La terminal de Mac usa zsh para entender lo que escribes; rc es la terminación tradicional de los archivos de arranque
Por qué no lo ves Empieza con punto: es un archivo oculto. En el Finder, Cmd + Shift + . los muestra
En Linux Su equivalente suele ser .bashrc

Para qué sirve: para que la terminal arranque como tú quieres. Por ejemplo, para crear atajos.

Tres cosas que conviene saber:

  1. Los cambios se aplican en terminales nuevas. Si lo editas con una terminal abierta, abre otra o pídele que lo vuelva a leer (source ~/.zshrc).
  2. No es el único archivo. Existe .zprofile, que se lee justo antes. Algunos instaladores, como el de Homebrew, dejan ahí sus instrucciones.
  3. Si escribes algo mal, la terminal muestra un error al abrirse. No se rompe nada: corriges el archivo y listo.

Y una de las cosas que se configuran ahí no es un atajo: es la lista de carpetas donde la terminal busca los programas. Esa lista se llama path.

2. Lo instalé y no funciona

Instalas un programa, escribes su nombre y la terminal responde:

zsh: command not found: programa

Pero si escribes la ruta completa (su carpeta y su nombre), funciona. El programa existe; la terminal no lo encuentra.

2.1 Cómo busca la terminal

Cuando escribes solo el nombre, la terminal no busca en todo el disco. Recorre el path de arriba hacia abajo y, en cada carpeta, pregunta si hay un programa con ese nombre. Usa el primero que encuentra. Si llega al final sin encontrarlo: command not found.

Qué significa
Instalar Tener el programa en tu disco
Poder usarlo Que esté en una carpeta del path

2.2 Ver tu path

echo $PATH | tr ':' '\n'

Muestra las carpetas una debajo de otra. En mi Mac salen 15: unas las puso el sistema, otras Homebrew y otras se agregaron después. Tres no existen y una está repetida; a la terminal no le importa: salta las que no existen y no vuelve a revisar las repetidas.

2.3 Por qué la lista es tan corta

Porque guarda carpetas, no programas, y en cada carpeta hay muchos. En mi Mac, las carpetas que existen suman más de 1.800 comandos.

Caso Qué pasa al instalar
Homebrew (la mayoría) Deja el programa en su carpeta, que ya está en el path: funciona sin tocar nada
Programas de los que puedes tener varias versiones a la vez (PostgreSQL) Homebrew no lo pone en su carpeta, para que las versiones no choquen. Te avisa que agregues tú la carpeta de la versión que quieres

3. Lo que hay dentro de esas carpetas: el acceso directo

El path no guarda programas: guarda direcciones de carpetas. Lo que hay dentro depende de quién puso la carpeta.

Grupo Ejemplo Qué hay dentro
Sistema /usr/bin, /bin El programa real, no un acceso directo. Protegidas
Homebrew /opt/homebrew/bin Lo que instalas con Homebrew
Compartida /usr/local/bin Para toda la Mac (el instalador pide contraseña). Ej.: docker (app con ventanas) y python3 (instalador de python.org)
Las tuyas ~/.local/bin Solo para tu usuario. Lo que instalas con el comando de instalación de la página oficial

En las tres últimas casi nunca está el programa: hay un acceso directo.

3.1 Qué es

Como el acceso directo del escritorio de Windows o el alias de Mac: no es el programa, pero te lleva a él. Su nombre técnico es enlace simbólico (symlink).

Ejemplo: Visual Studio Code vive en Aplicaciones. Cuando activas su comando, en /usr/local/bin aparece code, un acceso directo a la aplicación.

3.2 Cómo se crea

No basta con escribir la ruta en un archivo de texto: eso sería solo un texto. Se crea con ln -s:

ln -s "/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" /usr/local/bin/code
Parte Qué es
ln -s Crea un enlace simbólico
Primera ruta Dónde está el programa de verdad
Segunda ruta Dónde queda el acceso directo y cómo se llama

El nombre del acceso directo es el comando. Si lo llamaras abracadabra, escribirías abracadabra para abrir el programa.

Para ver a dónde apunta uno:

ls -l ~/.local/bin/claude

~/.local/bin/claude -> ~/.local/share/claude/versions/2.1.327

Para qué sirve: el programa vive donde quiera y tú lo usas siempre con el mismo nombre. Claude Code guarda cada versión en un archivo con su número; al actualizarse, el acceso directo claude pasa a apuntar a la nueva y tú sigues escribiendo claude.

3.3 Enlaces rotos

Si borras el programa, el acceso directo no se entera. En mi Mac borré dos aplicaciones arrastrándolas a la papelera y quedaron nueve accesos directos apuntando a nada.

Situación Qué responde la terminal
Escribes el nombre command not found
Escribes la ruta completa del enlace no such file or directory

Si compruebas que el programa ya no está donde apunta el enlace, puedes borrar el enlace: solo borras el acceso directo. En la carpeta compartida pide contraseña de administrador.

En Linux los accesos directos funcionan igual (ln -s).

4. El comando que pegas para arreglar el path

Instalas un programa con el comando de su página oficial, termina bien y al final aparece un aviso: la carpeta donde quedó no está en tu path. Te da un segundo comando. Lo pegas, abres otra terminal y funciona.

4.1 Qué pasó

Paso Qué hace
1. El instalador Guarda el programa en una carpeta y deja su acceso directo en otra. Para el path importa la del acceso directo
2. Qué carpeta La decide quien hizo el programa: muchos usan ~/.local/bin, otros una carpeta propia
3. Si no existe La crea. No es el problema
4. ¿Está en el path? Si ya está, funciona. Si no: unos instaladores la agregan solos; otros te dan el segundo comando

4.2 El segundo comando

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc

No instala nada. Escribe una instrucción (una línea de texto) al final de tu .zshrc:

export PATH="$HOME/.local/bin:$PATH"
Se escribe Una sola vez
Se aplica En cada terminal que abres, porque todas leen el .zshrc
La terminal que ya estaba abierta No funciona: leyó el archivo antes de que existiera la instrucción

4.3 Lo que viene después

Caso Qué pasa
Otro programa que también usa ~/.local/bin Nada que hacer: la carpeta ya está en el path
Un programa con carpeta propia La primera vez no está en el path: necesita su propia instrucción en el .zshrc. En mi Mac pasa con PostgreSQL

No es la única manera de agregar una carpeta al path, pero es la que vas a encontrar en estos avisos.
