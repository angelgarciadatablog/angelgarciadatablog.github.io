Quién está en mi servidor: crear usuarios, moverse entre ellos y cerrar sesiones

datablog sistemas-y-redes
Actualizado: 2026-11-09

En los ejemplos, el administrador se llama admin-angel y el servidor, mi-servidor. Las salidas son reales, con esos nombres cambiados.

1. Crear un usuario

1.1 El punto de partida

En muchos proveedores, un VPS nuevo trae un solo usuario: root, el dueño de todo. Lo normal es crear un usuario propio para el día a día con permisos de administrador. Aquí ese usuario es admin-angel.

Ahora llega alguien nuevo, claudia. Lo crea admin-angel:

sudo adduser claudia
Parte Qué hace
sudo Lo ejecuta con permisos de administrador
adduser Crea un usuario (add user, agregar usuario)
claudia El nombre del usuario

Pide una contraseña y unos datos opcionales que se pueden dejar en blanco.

1.2 Qué nace con ese comando

Qué nace Ejemplo Para qué sirve
El usuario claudia, número 1001 Su identidad: tú usas el nombre; el servidor, el número
Su carpeta personal /home/claudia Su espacio en el servidor
Su grupo personal grupo claudia, número 1001 Cada archivo que cree queda por defecto en ese grupo

El usuario y su grupo se llaman igual, pero son dos cosas distintas.

1.3 La ficha de un usuario: id

id claudia
uid=1001(claudia) gid=1001(claudia) groups=1001(claudia),100(users)
Campo Qué es
uid Número de usuario
gid Número de su grupo principal
groups Todos sus grupos

users es un grupo general que adduser agrega solo y que no da permisos especiales. La diferencia con el administrador está en esta lista: admin-angel aparece además en el grupo sudo, y ese es el que le da permisos de administrador.

1.4 Qué puede hacer un usuario recién creado

Puede No puede
Todo dentro de su carpeta personal Entrar a la carpeta de otro usuario (Permission denied)
Recorrer las carpetas del servidor Tocar el firewall
Ver qué otros usuarios existen Leer archivos protegidos del sistema
Leer muchos archivos de configuración Usar sudo

Si intenta usar sudo, el servidor responde:

claudia is not in the sudoers file.

Un usuario nace sin permisos de administrador. Esos permisos se los da el administrador.

2. Moverse entre usuarios

2.1 Saber quién eres

La línea de la terminal empieza con el nombre del usuario y termina con un símbolo:

Símbolo Qué indica
$ Un usuario normal
# root: el servidor ya no te frena

Para confirmarlo, whoami (who am I, quién soy) imprime el usuario actual.

2.2 Los tres comandos

Comando Qué hace Qué contraseña pide
sudo -i Pasar a root La de quien lo escribe (admin-angel)
su - claudia Pasar a otro usuario La del usuario al que cambias (claudia)
exit Volver un paso atrás Ninguna

Cada cambio es una capa encima de la anterior. sudo -i pone una capa de root sobre admin-angel y exit la quita. Cambiar de carpeta con cd no cambia de usuario.

sudo y su no piden lo mismo. sudo confirma que eres tú y después revisa si tienes permiso. su solo te pide la contraseña del usuario destino. Por eso sudo funciona aunque root tenga la contraseña bloqueada.

2.3 Por qué no entrar directo como root

En este servidor, root no puede entrar por SSH: primero se entra como admin-angel y desde ahí se pasa a root. Así, para usar sudo como administrador, alguien necesitaría dos cosas: entrar como admin-angel y conocer su contraseña.

2.4 El mismo comando, distinto resultado

admin-angel@mi-servidor:~$ sudo whoami
root

claudia@mi-servidor:~$ sudo whoami
[sudo] password for claudia:
claudia is not in the sudoers file.

Lo que cambia es quién lo escribe. Antes de escribir un comando, mira con qué usuario estás.

3. Quién está conectado ahora

3.1 who

who (quién) muestra una línea por cada sesión abierta. No es lo mismo que whoami: este dice quién eres tú; who, quién inició sesión en el servidor.

admin-angel  pts/0  2026-11-08 10:46 (198.51.100.20)
admin-angel  pts/1  2026-11-08 11:43 (192.0.2.30)
Columna Qué es
admin-angel Usuario con el que se inició sesión
pts/0 Terminal de esa sesión
2026-11-08 10:46 Hora de entrada (en el servidor suele estar en UTC)
198.51.100.20 IP desde donde se conectó

No hace falta ser administrador: cualquier usuario puede ver quién está conectado.

3.2 Lo que who no te dice

  • Muestra el usuario con el que se entró, no con cuál se trabaja. Si entras como admin-angel y te cambias a claudia, who sigue mostrando admin-angel.
  • Muestra el usuario, no la computadora. La misma persona desde dos computadoras aparece dos veces con el mismo nombre.

3.3 Una IP distinta no es un intruso

Puede ser la laptop del trabajo, otra red o una VPN. Antes de alarmarte, revisa qué IP tiene tu otra computadora. Si coincide, esa sesión es tuya. Si no coincide con ninguna, toca actuar.

4. Cerrar una sesión que no es tuya

4.1 Identificarla

Cada sesión tiene su terminal virtual: pts/0, pts/1… (pseudoterminal). Aunque dos sesiones tengan el mismo usuario, ese número las distingue.

Antes de cerrar nada, mira cuál es la tuya:

tty
/dev/pts/0

4.2 Cerrarla

sudo pkill -KILL -t pts/1
Parte Qué hace
sudo Hace falta: la sesión puede ser de otro usuario
pkill Termina procesos
-KILL Envía una señal que no se puede ignorar
-t pts/1 Solo los procesos de esa terminal

Sin -KILL no la cierra. Por defecto pkill solo le pide a la sesión que termine (SIGTERM), y una terminal abierta ignora esa petición. En mi servidor, who seguía mostrando la sesión; con -KILL desapareció.

4.3 Cerrarla no basta

Si alguien entró, es porque tenía una forma de entrar, y puede volver en un minuto. Cerrar la sesión es el primer paso; después hay que revisar quién tiene acceso y cambiar las credenciales.
