Nuestra primera petición a una API con Python

datablog apis
Actualizado: 2026-10-25
En video corto · 3

1. Las cuatro partes de una petición

Una petición puede tener cuatro partes, pero no todas las usan:

Parte Qué es
Método Qué quieres que haga la API (GET, POST…)
Dirección Dirección base + endpoint (+ parámetros, si hacen falta)
Headers Datos sobre la petición: quién eres, en qué formato envías
Cuerpo Lo que envías a la API. Un GET no lleva

2. La primera petición: Pikachu en la PokeAPI

Qué endpoints existen lo dice la documentación de cada API. En la PokeAPI:

Endpoint Qué devuelve
/pokemon/pikachu Un Pokémon
/type/fire Los Pokémon de tipo fuego (109)

La petición en Python, con la librería requests:

import requests

respuesta = requests.get("https://pokeapi.co/api/v2/pokemon/pikachu")
Parte En esta petición
Método ✅ GET
Dirección ✅ https://pokeapi.co/api/v2 + /pokemon/pikachu
Parámetros ❌ No hicieron falta
Headers ❌ Ninguno escrito: esta API no pide identificarte y requests pone los suyos
Cuerpo ❌ Un GET no lleva

Dos de cuatro partes bastan para tener una respuesta.

Nota: se instala con pip install requests

3. La respuesta es un sobre cerrado

Lo que devuelve requests no son los datos todavía:

>>> type(respuesta)
<class 'requests.models.Response'>
>>> respuesta
<Response [200]>

Adentro trae tres cosas, y se abren en este orden:

Orden Qué miras Cómo En Pikachu
1 El código de estado respuesta.status_code 200
2 El formato (header Content-Type) respuesta.headers.get("Content-Type") application/json; charset=utf-8
3 El cuerpo, con los datos datos = respuesta.json() Un diccionario

Por qué en ese orden:

  1. Si el código es un error, el cuerpo no trae tus datos, sino el mensaje de error. Ejemplo: /pokemon/pikachuuu devuelve 404 y {'status': 404, 'message': 'Not Found'}.
  2. .json() no mira el Content-Type: intenta leer el cuerpo como JSON y, si no lo es, falla.

4. Explorar un JSON enorme por niveles

El cuerpo de Pikachu tiene 15.580 líneas (con sangría), y el 93 % es la lista de movimientos. No se imprime entero: se explora por niveles.

Paso Qué preguntas Código Resultado
1 ¿Qué es? type(datos) dict
2 ¿Qué claves tiene? (sin el contenido) datos.keys() id, name, height, moves, stats, types…
3 Es una lista: ¿cuántos elementos? len(datos["types"]) 1
4 Mira uno solo datos["types"][0]["type"]["name"] 'electric'

Con una lista, basta mirar un elemento: los demás tienen la misma forma. Para sacar todos los movimientos:

for movimiento in datos["moves"]:
    print(movimiento["move"]["name"])   # 109 nombres

Para explorar la respuesta hace falta un poco de Python: diccionarios, listas y moverse entre ellos.

5. Las credenciales que te vas a encontrar

La PokeAPI no pide identificarte. Muchas otras sí: sin credencial responden 401 (no sé quién eres). Cada API la entrega de una forma distinta:

API Qué haces Qué obtienes ¿Vence?
Notion Creas una integración y le das acceso a las páginas que quieras El token, directo No, hasta que lo borres
Spotify (catálogo) Creas una app → recibes Client ID + Client Secret → los cambias por un token con un POST Un token de la app Sí, en 1 hora
TikTok (tus datos) Creas una app → recibes Client ID + Client Secret → inicias sesión y aceptas los permisos Un token para tus datos Sí, en 24 h (se renueva con el refresh token, que dura 1 año)

Qué es una "aplicación" de desarrollador

No es una app del celular ni tu código: es un registro en el panel para desarrolladores de la API, con un nombre. Al crearlo recibes un Client ID y un Client Secret, que funcionan como el usuario y la contraseña de ese registro. Tu código los usa para pedir el token.

Nota: Client ID + Client Secret ≠ token

Con el token de Spotify obtenido así puedes pedir el catálogo (artistas, canciones, álbumes), pero no tus datos personales: eso devuelve 401. Para tus datos hace falta iniciar sesión, como en TikTok.

6. Dónde viaja la credencial

Casi siempre en los headers. Notion, Spotify y TikTok la piden en el header Authorization, con la palabra Bearer delante:

Authorization: Bearer <token>

Bearer significa portador: quien trae la credencial, puede entrar. Otras APIs usan un header con otro nombre; cuál usar lo dice la documentación.

Las cuatro partes en una sola petición: buscar en Notion

Para buscar en Notion el método es POST, aunque lo que quieres son datos: le envías lo que quieres buscar, y con eso te responde.

import keyring, requests

token = keyring.get_password("apis-para-analistas", "notion-token")

respuesta = requests.post(
    "https://api.notion.com/v1/search",              # método + dirección
    headers={
        "Authorization": f"Bearer {token}",          # la credencial
        "Notion-Version": "2026-03-11",              # la versión de Notion
    },                                               # Content-Type lo pone requests
    json={"query": "..."},                           # el cuerpo
)
Parte En esta petición
Método POST
Dirección https://api.notion.com/v1/search
Headers El token (Authorization), la versión de Notion (Notion-Version, obligatoria en cada petición) y el formato del cuerpo (Content-Type: application/json, que requests pone al usar json=)
Cuerpo Lo que quieres buscar

El token nunca va escrito en el código

El token permite pedir datos en tu nombre. Por eso hay tres cosas distintas:

Qué Dónde
Dónde se guarda En un lugar seguro de tu computadora (en Mac, el Llavero), si trabajas en local
Cómo llega al código En una variable: token = keyring.get_password(...)
Dónde viaja En el header: f"Bearer {token}"

En el código solo está la variable, nunca el valor. Dónde guardar la credencial en local y en producción se verá más adelante en la serie.
