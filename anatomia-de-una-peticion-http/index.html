Anatomía de una petición HTTP

datablog apis
Actualizado: 2026-10-21
En video corto · 2

1. Qué es una petición

Una petición es el mensaje que le envías a una API. Toda petición deja claras dos cosas:

  1. A qué dirección va.
  2. Qué quieres que haga la API: el método.

2. La dirección

Cada recurso que ofrece una API tiene su propia dirección, llamada endpoint. Ejemplo real: la población de Perú en la API del Banco Mundial.

https://api.worldbank.org/v2/country/PER/indicator/SP.POP.TOTL?format=json&date=2020:2024
Parte En el ejemplo Qué hace
Dirección base https://api.worldbank.org/v2 Es la misma para todo lo que pidas a esa API
Endpoint /country/PER/indicator/SP.POP.TOTL Dice qué quieres: un país y un indicador
Parámetros ?format=json&date=2020:2024 Afinan el pedido: formato y años

Qué partes van y cómo se escriben lo dice la documentación de cada API.

3. El método

Método Para qué
GET Pedir algo que ya existe
POST Enviar algo: para crearlo o para que la API lo procese y devuelva un resultado
PUT / PATCH Actualizar algo que ya existe
DELETE Borrar

Como analista usarás casi siempre GET. Pero POST también sirve para pedir cuando hay que enviar algo para obtener la respuesta:

Caso Lo que envías con POST Lo que recibes
API de ChatGPT Tu pregunta La respuesta
Búsqueda en Notion El texto a buscar Las páginas que coinciden

4. Qué devuelve una API

La respuesta trae tres cosas:

  1. El código de estado: cómo salió la petición.
  2. El cuerpo: los datos.
  3. El header Content-Type: el formato de esos datos.

El código de estado

Es lo primero que hay que mirar cuando algo falla. Basta con el primer dígito:

Empieza con Significado Ejemplos
2 Todo salió bien 200: la PokeAPI devuelve los datos de Pikachu
4 El error es tuyo 404 no existe (un Pokémon inventado) · 401 no te identificaste · 403 te identificaste, pero no tienes permiso · 429 pediste demasiado
5 El error es del servidor 500: la API falló; toca reintentar más tarde

Los más comunes:

Código Significado
200 Éxito
201 Creado correctamente (respuesta a un POST)
400 Error en tu petición: un parámetro mal escrito o que falta
401 No te identificaste
403 Te identificaste, pero no tienes permiso
404 Lo que pediste no existe
429 Pediste demasiado (superaste el límite de peticiones)
500 Error del servidor, no tuyo

El cuerpo y su formato

Casi siempre llega en JSON (nombres y valores), pero no siempre: por eso conviene revisar Content-Type o la documentación antes de usar los datos. Algunas APIs dejan elegir el formato, como el Banco Mundial con format=json.

Los datos vienen envueltos

Casi nunca llegan sueltos: vienen dentro de otra estructura, junto con información sobre la respuesta.

API Dónde están los datos
YouTube, Spotify Dentro de items
Notion Dentro de results
Banco Mundial En el segundo elemento de una lista; el primero es la paginación

Antes de procesar, ubica dónde están los datos que buscas.

5. Lo que falta

Todo esto basta para las APIs públicas. Las que piden identificarte (autenticación) se verán más adelante en la serie.
